# 保持 Pi 为宿主，并将 Pi Stuff 保持为一个由仓库负责的软件包

## 背景

Pi 已经负责 CLI、TUI、会话、设置层、软件包加载和模型交互。Pi Stuff 作为一个套件进行安装、升级、测试和使用；它的任何能力都没有独立的用户、发布或安装生命周期。把套件拆成多个 npm 软件包，或者仅为了减少仓库代码行数而把机制移到上游，都会增加边界，却不会产生独立产品。

源代码的来源也不会改变维护责任。无论是改编、分叉、内嵌、生成还是本地编写的源码，都从本仓库交付，并且都可能影响同一个宿主行为。

## 决策

Pi 继续作为宿主。Pi Stuff 继续作为一个本地 Pi 软件包，并只提供一个默认扩展工厂。入口点通过 Pi 的公开扩展接口，按顺序安装内部能力模块；它不会引入另一套 CLI、运行时、会话层、SDK 或 TUI 外壳。

能力模块是内部实现边界，不是可独立安装或发布的软件包。当前有序集合由 `packages/pi-stuff/suite.json` 定义，模块间依赖保持明确。共享模块可以向能力模块提供范围狭窄的接口，但共享模块不得导入使用它们的能力。经过改编的 MCP 和 Web 实现仍放在各自所属模块的私有目录中。

每一份受跟踪的实现、测试、脚本、生成源码、原型和仓库质量工具，无论来源如何，都是仓库负责的源码。它们都遵守相同的架构、格式、Lint、类型安全、依赖、规模和可维护性门槛。来源信息仍然必须保留，用于归属、许可证和选择性上游审查；它绝不构成质量豁免。

扩展导入必须保持纯净。软件包安装和设置层变更必须由宿主或维护者显式执行；初始化失败应直接传播，不能留下只加载了一部分的套件。

Conversation UI 在没有公开 renderer 时，可以适配已认证 Host 的 Thinking 与 User Message 展示方法。
这些范围狭窄、可撤销的适配器保留规范消息和 Host 生命周期权威，必须经过真实 Host 认证，并在 Session 关闭时
释放方法所有权。这个展示例外不授权修改执行、持久化或任意 Host 内部机制。User Message 的取舍和异常保护
见 [ADR 0030](0030-unify-user-message-presentation.md)。

## 后果

- Pi 继续负责普通宿主行为和生命周期权威。
- 仓库保留一个开发清单和一个运行时软件包清单；不采用 npm 发布、Changesets、逐能力版本或多软件包发布清单。
- 运行时依赖只声明一次。测试验证公开宿主和模块接缝，而不是 npm 软件包名称。
- 选择性审查并吸收上游修复，不引入第二套软件包生命周期。
- 只有出现真实的独立消费者或安装需求时，某项能力才可以变成软件包。
- 仓库精简应来自删除不需要的行为、加深模块以及复用公开或原生接缝，而不是为了满足行数目标而转移代码所有权。

## 被拒绝的替代方案

- **每项能力一个工作区软件包：** 用户面对的部署和发布单元仍然是一个套件，因此额外的清单、版本、依赖边和归档没有独立生命周期可表达。
- **为减少源码而外置机制：** 这只会转移维护责任，不会降低产品复杂度，也不会改变必须验证这些行为的人。

## 合并历史

本 ADR 吸收了原 ADR 0003（一个本地软件包及其内部能力模块）和 ADR 0016（仓库所有权不取决于来源）中的长期决策。它们描述的是同一个宿主与所有权边界，因此删除原独立文件。

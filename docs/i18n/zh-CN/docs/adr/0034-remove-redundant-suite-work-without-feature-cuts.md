# 消除 Suite 重复工作，不删减功能

集成时因 main 已占用 ADR 0030–0033，本已接受的 ADR 从 0030 重编号为 0034；决策及其证据引用保持不变。

## 背景

已完成的 Tool Display 修复之外仍反复出现 Vibe Line 卡顿，维护者于 2026-09-05 接受以下决定：
在不删减功能的前提下消除 Suite 重复工作，分别验证资源消耗与界面响应性。验收阈值必须在优化前校准；
本决定不代表实现或 Pi 0.85.0 认证已经完成。

## 决策

### 已确认范围

消除 Pi Stuff 全范围内无用的重复工作和内部资源开销，并消除 Suite 引入的界面卡顿，尤其是
Vibe Line Spinner 卡顿。目标不限于 ADR 0028 覆盖的 Tool Display 路径。

现有功能不属于本次删除候选。不得为了降低资源消耗而删除、禁用自动 Session Naming、自动用量刷新
或其他功能，也不得将它们改为手动操作。功能本身必需的成本不在删除范围内；在保持相同行为的前提下，
实现中的重复工作仍属于优化范围。安全、权限、数据完整性和规范 Session 记录保持不变。

仅把原有计算移到其他线程，并不意味着总资源消耗下降。资源效率和界面持续响应是两个独立要求，
必须分别提供证据。

维护者于 2026-09-06 澄清：上述区分不禁止执行隔离。必要且可独立执行的计算与依赖求值，优先采用最小的
现有 Worker 或子进程边界。输入、渲染和规范 Session 提交仍由 Pi 负责；`async` 或让出一次 timer turn
本身不等于并行执行。保留已有测量支持的简单去重，不把工作扩展成推测性缓存或无边界的微优化审计。
隔离改动必须分别验证输入、取消、恢复和数据一致性；即使内存或耗时上升，也要如实报告总资源成本。

### 已确认的资源取舍

当测量证明有收益时，允许保留少量、有界的内存来避免重复计算。优先复用已有状态。任何新增缓存都必须
有容量边界、正确的失效条件和明确的释放时机；不能通过随 Session 历史无限增长来避免重复工作。

### 已确认的目标 Host

最终验收以一个固定的 Pi 0.85.0 构建为目标，并包含兼容性核验。实现期间必须确定其精确二进制身份，
并对齐仓库兼容性契约。资源与响应性对照必须使用同一构建；Pi 0.84.4 或其他可执行文件的结果不能证明
该构建已经通过认证。这项决定本身不会升级、重启或替换任何正在运行的用户进程。

### 已确认的卡顿责任边界

本次工作必须消除由 Pi Stuff 引入或放大的卡顿。Suite 通过 Pi 原生 API 触发的重复渲染或扫描，仍属于
Suite 开销；调用 Host API 不会转移这部分额外工作的责任。

只有对照证明不加载 Pi Stuff 时也存在相同卡顿，才能归因为仅由 Host 引起的问题。这类问题必须单独
报告；只要它们仍存在，就不能声称整个 Pi 已经完全不卡顿。即使原生 Host 也卡顿，Suite 额外增加的
部分仍在本次范围内。

### 已确认的响应性门槛

只要观察到一次可归因于 Pi Stuff 的卡顿，就阻止交付，包括整体流畅运行中的偶发卡顿。
平均值或分位数改善不能抵消单次失败。

先测固定原生 Host 的正常节奏与观测误差，再锁定验收门槛。检查最长可见 spinner 停帧、最慢输入反馈和
选择反馈，而不只看汇总延迟。不得通过降低刷新率或放宽门槛来通过验收。资源节省不能免除响应性要求。

### 已确认的调度取舍

消除重复计算后，剩余必要工作可以拆成有界的小段，让界面在段与段之间继续响应，即使该操作的总完成
时间略有增加。这只适用于保持功能所必需、无法消除的工作。把浪费移到后台不算优化；在每次 Tool 调用
前插入固定等待，也不是可接受的响应性机制。

### 已确认的完成条件

只有同时满足以下条件，整项工作才算完成，而不是仅修复已观察到的 Execution Ledger 卡顿：

- 覆盖每个 Capability，以及启动、空闲、长 Session、Tool、Agent、Context 处理和恢复路径。
- 消除已确认的重复工作；说明保留开销的必要性，并提供优化前后的资源测量。尚未查清的项目不算完成。
- 保持功能不变，并在固定 Pi 0.85.0 构建上通过真实 Host 验收，不触发上述单次卡顿失败规则。

不得用任意设定的资源下降百分比替代逐项处理完成，也不得用聚焦测试通过来证明整项工作已经完成。

### 实现约束

按 `packages/pi-stuff/suite.json` 清点每个 Capability，既包括 Agent Tool 行，也包括 Agents 生命周期。
共享 Package 加载、注册、状态投影与清理同样在范围内。每条路径都记录归属、触发条件、随输入规模增长的
成本、重复工作、测量值，以及消除结果或保留理由。尚未测量的怀疑属于调查项，不是删除行为的许可。

优先在现有归属模块做增量更新，避免因为无关变化重建投影。Execution Ledger 查询是第一个已确认的例子：
新增普通 Session 消息，不应让未变化的账本事件重新经过完整规范化。保留外部数据边界校验、正确的分支与
Session 切换、审批和重放安全，以及规范历史。不可避免的初次重建同样必须覆盖响应性；热路径变快不能
抵消冷路径阻塞。

测量 Host 线程工作量和 Suite 总成本，后者包括 Worker 与子进程。报告 CPU 时间、稳态与峰值驻留内存、
分配与垃圾回收、I/O、唤醒次数和操作耗时，并写清测量限制。优化前后须保持功能、载荷、终端尺寸、缓存
条件和 Host 构建可比。离线夹具没有执行某项功能，就不能认证该功能。

从 Pi 事件循环外部观察可见界面，连续覆盖 Tool 执行前处理、执行和结束阶段。缺失 spinner 观察或观测
间隔过大时，样本只能判为不确定，不能算通过。保留单次最大值和失败轨迹；平均值只用于汇总资源成本。
短基线不能用于确定最终活性阈值，也不能证明没有偶发卡顿。

## 考虑过的替代方案

- 禁用自动功能：拒绝，因为这改变了产品，而不是消除重复工作。
- 整体搬到 Worker：不足以达标，因为总成本可能保持不变，甚至增加。
- 复用有界投影、消除重复工作，再拆分必要的长操作：选定，因为它在保留行为的同时处理资源消耗和响应性。
